# {{ pcsm.full_name }} 1.1.0 ({{ date.v1_1_0 }})

{{ pcsm.full_name }} (PCSM) 1.1.0 adds configurable target write concern and control over chunk pre-splitting during the initial clone, and fixes issues in cloning, pause handling, checkpoint recovery, and high availability.

[Get started with {{pcsm.short}}](../installation.md){.md-button}

## Release highlights

### Configurable write concern for target data writes

You can now configure the write concern for clone inserts and replication data writes. Using `1` can reduce stalls when target secondaries lag. The default remains `majority`.

Set the value using `pcsm start --target-write-concern=1`, `PCSM_TARGET_WRITE_CONCERN=1` for `pcsm start`, or `{"targetWriteConcern": "1"}` in the `/start` request body.

Checkpoints, high availability state, and catalog DDL operations always use `majority`. The run retains its setting during recovery and high availability takeover. To change it, start a new run.

!!! warning "Data rollback risk"
    Lower write concern can allow acknowledged data to roll back after a target primary failover, potentially requiring a new synchronization run. Use it only when restarting and validating the copy is acceptable. Avoid target primary stepdowns, keep the source available, and verify target consistency before cutover.

### Option to skip chunk pre-splitting during clone

When migrating between sharded clusters, you can now skip pre-splitting target collections to avoid copying poor chunk distribution from the source. The target balancer handles distribution later.

Use `pcsm start --clone-skip-presplit`, set `PCSM_CLONE_SKIP_PRESPLIT=true,` or include `"cloneSkipPresplit": true` in the `/start request` body.

PCSM still shards target collections using the source shard key. Pre-splitting remains enabled by default. This option is not saved in recovery checkpoints.

For more information about chunk distribution, see [sharding support](../sharding.md#chunk-distribution).


## Changelog

### Improvements

* [PCSM-128](https://perconadev.atlassian.net/browse/PCSM-128): Planned improvements to pause/resume and checkpoint recovery to address synchronization failures when replaying operations after a restart. Implementation and final release behavior are pending confirmation.
* [PCSM-311](https://perconadev.atlassian.net/browse/PCSM-311): Added configurable target data write concern through `pcsm start --target-write-concern`, the `PCSM_TARGET_WRITE_CONCERN` environment variable for `pcsm start`, and the `targetWriteConcern` field in the `/start` request body. Clone and replication bulk writes use the selected write concern, while checkpoint, high availability state, and catalog writes retain majority write concern. The default is `majority`, and the setting is preserved during recovery and high availability takeover.
* [PCSM-382](https://perconadev.atlassian.net/browse/PCSM-382): Added the `--clone-skip-presplit` option to `pcsm start`, the `PCSM_CLONE_SKIP_PRESPLIT` environment variable, and the `cloneSkipPresplit` field in the `/start` request body. You can skip target chunk pre-splitting during the initial clone while retaining the source shard key.

### Bugs fixed

* [PCSM-329](https://perconadev.atlassian.net/browse/PCSM-329): Fixed an issue where a source-side `getMore` error during the initial clone could leave PCSM running without making progress. When retries are exhausted, PCSM now propagates the error and reports the synchronization as failed.
* [PCSM-366](https://perconadev.atlassian.net/browse/PCSM-366): Fixed an issue where PCSM reported the synchronization as paused before replication had finished pausing. This could cause a subsequent resume request to fail because replication was still pausing.
* [PCSM-385](https://perconadev.atlassian.net/browse/PCSM-385): Fixed a deadlock when finalization was requested on a promoted standby instance after recovery. The `/finalize` request could previously hang and block subsequent `/status` requests. You can now reissue `/finalize` to resume interrupted finalization. PCSM also rejects concurrent finalization requests in the same instance.
* [PCSM-388](https://perconadev.atlassian.net/browse/PCSM-388): Fixed an issue where a PCSM instance that lost its high availability lease could continue writing user data to the target. These writes could overwrite newer data applied by the newly active instance and cause source and target data to diverge.
* [PCSM-389](https://perconadev.atlassian.net/browse/PCSM-389): Fixed checkpoint races that could stop recovery checkpointing shortly after synchronization started or allow an older state snapshot to overwrite a newer checkpoint. These issues could force a full re-clone after a restart or cause PCSM to lose the saved finalization state.
