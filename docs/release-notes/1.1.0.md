# {{ pcsm.full_name }} 1.1.0 ({{ date.v1_1_0 }})

We are pleased to announce **{{ pcsm.full_name }} (PCSM) 1.1.0**. This release lets you tune write durability and chunk pre-splitting for a migration. It also improves pause and resume and fixes several high availability issues that could stall finalization, stop checkpointing, or let a demoted instance write to the target.

[Get started with {{pcsm.short}}](../installation.md){.md-button}

## Release highlights

### Configurable target write concern

By default, PCSM uses the `majority` write concern for clone inserts and replication writes to the target cluster. If target secondaries lag behind, `majority` writes can stall and make PCSM hit the operation timeout, even when the target cluster has enough CPU and memory.

You can now set the write concern for data writes to the target for each run. Use one of these options:

* The `--target-write-concern` flag of the `pcsm start` command
* The `PCSM_TARGET_WRITE_CONCERN` environment variable
* The `targetWriteConcern` parameter in the `/start` request body

The value is either `majority` or a positive integer, for example, `1`. PCSM doesn't support unacknowledged writes (`0`). PCSM stores the value with the run and keeps it after checkpoint recovery and HA takeover. To change the value, start a new run. Checkpoints, HA state, and catalog DDL operations always use `majority`.

!!! warning

    With the `1` write concern, only the target primary acknowledges a write, so the data isn't majority-durable. If the target primary fails, MongoDB can roll back writes that it already acknowledged. Use `majority` when automatic recovery must preserve durability. Lower the write concern only for a controlled migration that you can restart and validate after a target failure. Keep the source cluster and verify that the target is consistent before cutover.

### Option to skip chunk pre-splitting

For migrations between sharded clusters, PCSM pre-splits sharded collections on the target using the source chunk boundaries. If the chunk distribution on the source is uneven, you might not want to copy it to the target.

You can now turn off pre-splitting with the `--clone-skip-presplit` flag of the `pcsm start` command, the `PCSM_CLONE_SKIP_PRESPLIT` environment variable, or the `cloneSkipPresplit` parameter in the `/start` request body. When you turn it off, the target keeps the chunk layout that MongoDB creates. Pre-splitting stays on by default.

For more information about migrations between sharded clusters, see [sharding support](../sharding.md).

### Improved high availability reliability

This release fixes several issues in [active-standby high availability](../high-availability.md):

* An instance that lost the lease can no longer write user data to the target. Previously, it could overwrite newer changes applied by the new active instance.
* After a standby instance is promoted during finalization, a new `finalize` request completes. Previously, it never returned and blocked the `status` command.
* PCSM keeps saving recovery checkpoints for the whole run. Previously, checkpointing could stop seconds after the run started, and a later restart required a new initial clone.

## Changelog

### Improvements

* [PCSM-128](https://perconadev.atlassian.net/browse/PCSM-128): Improved the pause and resume logic.
* [PCSM-311](https://perconadev.atlassian.net/browse/PCSM-311): Added the option to set the write concern for clone inserts and replication writes to the target cluster. Use the `--target-write-concern` flag, the `PCSM_TARGET_WRITE_CONCERN` environment variable, or the `targetWriteConcern` parameter in the `/start` request. The default remains `majority`. Checkpoints, HA state, and catalog DDL operations always use `majority`.
* [PCSM-352](https://perconadev.atlassian.net/browse/PCSM-352): Enabled the `contextcheck` linter for the PCSM codebase. The linter makes sure that cancellations and deadlines reach long-running operations, so that pause, finalize, and shutdown don't leave cursors or goroutines running.
* [PCSM-382](https://perconadev.atlassian.net/browse/PCSM-382): Added the option to skip chunk pre-splitting of sharded collections on the target. Use the `--clone-skip-presplit` flag, the `PCSM_CLONE_SKIP_PRESPLIT` environment variable, or the `cloneSkipPresplit` parameter in the `/start` request. Pre-splitting stays on by default.

### Bugs fixed

* [PCSM-329](https://perconadev.atlassian.net/browse/PCSM-329): Fixed an issue where PCSM stopped making progress during the initial clone when the source rejected a `getMore` command on a data cursor. PCSM logged the error, but `status` kept reporting the `running` state. PCSM now fails the run and reports the `failed` state.
* [PCSM-366](https://perconadev.atlassian.net/browse/PCSM-366): Fixed an issue where PCSM reported replication as paused before replication had fully stopped. A `resume` request sent during that time could fail. PCSM now reports the paused state only after replication stops.
* [PCSM-385](https://perconadev.atlassian.net/browse/PCSM-385): Fixed an issue where a `finalize` request never returned on a standby instance that was promoted while the previous active instance was finalizing. The `status` request on that instance also stopped responding. PCSM now resumes finalization after promotion.
* [PCSM-388](https://perconadev.atlassian.net/browse/PCSM-388): Fixed an issue where a PCSM instance that lost the HA lease could still write user data to the target. This could overwrite newer changes applied by the new active instance and leave the target inconsistent with the source. An instance that loses the lease now stops writing data to the target.
* [PCSM-389](https://perconadev.atlassian.net/browse/PCSM-389): Fixed an issue where PCSM stopped saving recovery checkpoints seconds after the run started. Two concurrent checkpoint writes in the same instance were treated as a takeover by another instance. Replication completed correctly, but a later restart required a new initial clone. A checkpoint from the finalizing stage could also overwrite the finalized checkpoint. PCSM now saves checkpoints throughout the run and keeps the latest state.
